# CardKB + TFT терминал на ESP32-S3-N16R8

Проект: клавиатура M5 Unit CardKB v1.1 (I2C) + TFT SPI дисплей 240×320
(ILI9341) на ESP32-S3-N16R8. Клавиатура выводит текст на экран,
поддерживает курсор, стрелки, вкл/выкл экрана, очистку и свои
комбинации клавиш. Enter используется как "отправка команды"
(заготовка под будущий ИИ-терминал), а не как перенос строки.

Актуальный рабочий скетч: **`cardkb_tft_display_v8.ino`**.

---

## 1. Подключение (распиновка)

| Сигнал | GPIO ESP32-S3 |
|---|---|
| TFT CS | 7 |
| TFT RESET | 5 |
| TFT DC | 6 |
| TFT SDI (MOSI) | 10 |
| TFT SCK | 9 |
| TFT SDO (MISO) | 8 |
| TFT VCC / LED | 3.3V |
| TFT GND | GND |
| CardKB VCC | 3.3V |
| CardKB GND | GND |
| CardKB SDA | GPIO1 |
| CardKB SCL | GPIO2 |

> ⚠️ LED (подсветка) дисплея подключена напрямую к 3.3V, не к GPIO.
> Поэтому программно физически погасить подсветку нельзя — "выключение
> экрана" по Esc делает это чисто визуально (чернит пиксели), не
> экономя энергию. Для настоящего управления подсветкой нужно
> перекинуть провод LED на свободный GPIO.

## 2. Библиотеки (Arduino IDE → Library Manager)

- **Adafruit GFX Library**
- **Adafruit ILI9341** (если у вас драйвер ST7789 — используйте
  `Adafruit_ST7789`, инициализация почти такая же)
- **Adafruit BusIO** (ставится как зависимость)
- `Wire.h` — часть ядра ESP32, ставить не нужно

Ядро платы: **esp32 by Espressif Systems**, плата — **ESP32S3 Dev
Module**, PSRAM: **OPI PSRAM** (так как N16R8), Flash Size: **16MB**.

## 3. Как устроена клавиатура физически

На CardKB **три разные** клавиши, которые легко перепутать:

| Клавиша | Расположение | Как работает |
|---|---|---|
| **Esc** | верхний левый угол | обычная клавиша, код `0x1B` |
| **Tab** | слева, под Esc | обычная клавиша, код `0x09` |
| **Sym** | внизу слева, рядом с Z | НЕ модификатор в полном смысле: просто подсказывает прошивке, какой альтернативный символ напечатать для **конкретной** клавиши (только у тех клавиш, где нарисован мелкий значок — цифры, запятая, Q/W/E...). Готовый символ уже попадает в диапазон `0x20–0x7E` и печатается как обычный текст. **У Sym нет своего отдельного кода** — она не действует на клавиши без нарисованного альт-символа (например, на Enter). |
| **fn** | вверху справа, рядом с P | настоящий аппаратный модификатор. fn+буква (и fn+Enter) дают **единый уникальный байт**, которого не бывает при обычном нажатии — такие коды надо один раз откалибровать и внести в таблицу. |

Других клавиш-модификаторов (Ctrl и т.п.) на плате физически нет.

## 4. Таблица кодов клавиш

| Клавиша | Код (hex) |
|---|---|
| Обычный символ (буквы/цифры/знаки, включая готовые Sym-варианты) | `0x20`–`0x7E` |
| Backspace | `0x08` |
| Tab | `0x09` |
| Enter | `0x0D` |
| Esc | `0x1B` |
| Стрелка влево/вверх/вниз/вправо | `0xB4` / `0xB5` / `0xB6` / `0xB7` |

Коды стрелок — типовые для прошивки CardKB v1.1, но могут отличаться на
конкретном экземпляре. Если что-то не совпадает — см. раздел 8.

## 5. Как работает код (архитектура)

```
readCardKB() [опрос I2C каждые 5мс]
        │
        ▼
   handleKey(code)
        │
   ┌────┴─────────────────────────┐
   │                               │
 code == Esc              обычная обработка
   │                               │
handleEscKey()      seqPending? ──┐│
(двойной/одиночный   да │        ││
 тап, раздел 7)          ▼        ││
                   trySeqCombo    ││
                   (раздел 9)     ││
                         │ нет    ││
                         ▼        ││
              dispatchStandaloneKey(code)
                         │
        ┌────────────────┼─────────────────┐
        │                │                 │
  Backspace/Enter/   0x20-0x7E        tryFnBinding(code)
  стрелки (switch)    typeChar()      (раздел 8: fn+буква)
```

- **`screenBuffer[row][col]`** — весь видимый текст хранится в памяти,
  это позволяет восстанавливать экран после выключения/очистки.
- **Отрисовка посимвольная** (`drawCell`) — экран не чистится целиком
  на каждое нажатие, только изменённая ячейка. Это критично для
  скорости: при полной перерисовке клавиатура не успевает опрашиваться
  и теряет быстро набираемые буквы.
- **Курсор** — просто инверсия цветов текущей ячейки, мигает через
  `millis()` (без `delay`, чтобы не блокировать опрос).

## 6. Назначение клавиш сейчас

| Клавиша | Действие |
|---|---|
| Буквы/цифры/знаки | печать символа в текущей позиции курсора |
| Backspace | стереть символ перед курсором |
| Стрелки | двигать курсор по экрану (без удаления текста) |
| **Enter** (один раз) | `submitQuest()` — "отправка команды" (заглушка под будущий ИИ-терминал, раздел 10) |
| **fn+Enter** | перенос строки (`newLine()`) — обычное "перевод каретки" теперь на модификаторе, а не на голом Enter |
| Esc (один раз, пауза ~400мс) | включить/выключить экран (содержимое сохраняется) |
| Esc дважды подряд (<400мс) | очистить экран |
| fn+H | пример: приветствие в Serial (заглушка под свою функцию) |
| fn+T | пример: заглушка под свою функцию |
| Tab+C | пример: очистка экрана через обычную последовательность клавиш |

## 7. Esc: вкл/выкл и очистка (двойной тап)

Esc — обычная клавиша без модификатора, поэтому "одно нажатие" и
"два нажатия подряд" различаются по **времени**, не по коду:

```cpp
void handleEscKey() {
  if (escPending && (millis() - escPendingTime <= doubleTapWindow)) {
    escPending = false;
    clearBuffer();            // второй Esc за 400мс -> очистка
    if (displayOn) fullRedraw();
  } else {
    escPending = true;        // первый Esc - ждём второго
    escPendingTime = millis();
  }
}

void checkEscTimeout() {      // вызывается каждую итерацию loop()
  if (escPending && (millis() - escPendingTime > doubleTapWindow)) {
    escPending = false;
    toggleDisplay();          // время вышло - это было одиночное нажатие
  }
}
```

## 8. fn+буква — рекомендуемый способ для НОВЫХ комбинаций

fn physически склеивает нажатие в один байт — никаких таймеров не
нужно, это просто ещё один код в таблице:

```cpp
struct FnBinding {
  uint8_t code;
  void (*action)();
  const char* description;
};

FnBinding fnBindings[] = {
  { FN_H,     fnSayHello,        "fn+H - тестовое приветствие" },
  { FN_T,     fnInsertTimestamp, "fn+T - заглушка под свою функцию" },
  { FN_ENTER, newLine,           "fn+Enter -> перенос строки" },
};
```

**Как добавить свою комбинацию fn+буква (4 шага):**
1. Зажмите fn и нужную клавишу, посмотрите код в Serial Monitor
   (115200 бод) — появится `Неизвестный код: 0x..`, это и есть
   нужное значение (пока комбинация не добавлена в таблицу).
2. Впишите код в свой `#define`.
3. Напишите функцию без аргументов со своей логикой.
4. Добавьте одну строку в `fnBindings[]`.

Больше ничего менять не нужно — диспетчер `tryFnBinding()` подключён
один раз и обрабатывает все строки таблицы автоматически.

> ⚠️ Так же, как Sym не действует на Enter (раздел 3), fn может не
> подействовать на какие-то другие клавиши — это нужно проверять
> калибровкой для каждой конкретной задуманной комбинации.

## 9. Комбинации из двух ОБЫЧНЫХ клавиш подряд (без fn)

Нужны только тогда, когда обе клавиши — самостоятельные, с разными
кодами (как Tab и C). Работает через ожидание второй клавиши по
таймеру (аналогично Esc, но обобщённо на любую пару):

```cpp
struct SeqCombo {
  uint8_t firstKey;
  uint8_t secondKey;
  void (*action)();
  const char* description;
};

SeqCombo seqCombos[] = {
  { KEY_TAB, 'c', seqTabC, "Tab+C - пример" },
};
```

**Важное ограничение:** если одна из клавиш пары — "мягкий" модификатор
вроде Sym, который не имеет своего кода и не меняет код второй клавиши
(как с Enter) — эта таблица такую пару в принципе не различит, коды
будут идентичны. Для подобных случаев нужен именно fn (раздел 8).

**Как добавить комбинацию (3 шага):**
1. Функция без аргументов со своей логикой.
2. Строка в `seqCombos[]`: `{ ПЕРВАЯ, ВТОРАЯ, функция, "описание" }`.
3. Готово — движок (`trySeqCombo`/`isSeqFirstKey`/`checkSeqTimeout`)
   уже подключён и работает для всех строк таблицы.

> ⚠️ Не добавляйте в эту таблицу клавишу, у которой уже есть
> "мгновенное" действие (как Enter → submitQuest), если не хотите,
> чтобы это действие стало срабатывать с задержкой до `seqWindow` (400
> мс) — именно так и была найдена одна из прошлых ошибок в этом
> проекте: тестовая комбинация Enter+R делала КАЖДЫЙ Enter "подвисшим"
> на 400 мс в ожидании второй клавиши.

## 10. Следующий шаг: превращение в терминал (currentLine)

Сейчас каждый символ сразу рисуется на экране. Для полноценного
терминала нужен ещё один уровень — накопление вводимой строки
отдельно от экрана, и обработка её целиком по Enter:

```cpp
String currentLine = "";

void handleTypedChar(char c) {
  currentLine += c;
  typeChar(c);
}

void handleBackspaceKey() {
  if (currentLine.length() > 0) {
    currentLine.remove(currentLine.length() - 1);
    backspace();
  }
}

void submitQuest() {
  String command = currentLine;
  currentLine = "";
  Serial.print("Отправлена команда: ");
  Serial.println(command);
  // сюда позже: WiFi.h + HTTPClient.h -> запрос к ИИ,
  // разбор ответа (например, ArduinoJson) и вывод его на экран
}
```

Подключать через обёртки вместо прямых вызовов в
`dispatchStandaloneKey()`:

```cpp
case KEY_BACKSPACE: handleBackspaceKey(); break;
...
default:
  if (c >= 0x20 && c <= 0x7E) { handleTypedChar(c); }
```

## 11. Диагностика и частые проблемы

| Симптом | Причина / решение |
|---|---|
| `Неизвестный код: 0x..` в Serial Monitor | Нормальное поведение для нераспознанной клавиши — это и есть калибровочное значение, впишите его в нужный `#define` |
| Permission denied при загрузке (`/dev/ttyACM0`) | Добавить пользователя в группу `uucp`/`dialout` (`sudo usermod -aG uucp $USER`), перелогиниться |
| Буквы теряются при быстрой печати | Экран чистится целиком на каждое нажатие — используйте посимвольную отрисовку (`drawCell`), а не `fillScreen` в цикле |
| Комбинация не срабатывает, хотя код правильный | Проверьте, не "перехватывает" ли её другая запись в таблице раньше (например, две строки с одинаковой первой клавишей в `seqCombos[]`) |
| Один и тот же код у "комбинации" и у обычного нажатия | Модификатор (как Sym для Enter) физически не действует на эту клавишу — нужен другой модификатор (fn) или другая клавиша |
| Экран рисует "мусор" / неверные цвета | Вероятно драйвер ST7789, а не ILI9341 — замените библиотеку на `Adafruit_ST7789` |
